Is it working?

Where the database lives

Inside this page. Every claude.ai artifact can carry its own document database; this one does. The documents are JSON, grouped in collections, stored by claude.ai with the artifact and kept across republishes. They are readable by whoever can open this page and writable only by the owner and by Claude sessions acting as the owner.

Nothing here lives on GitHub or Drive at read time. GitHub main stays the record the routines write first; after each run a helper turns those files into documents and the run stores them here in one call. Drive keeps what must never be in a shared page (patient names, facesheets, HL7 files); this database holds chart ids, dates, codes and dollars only.

How it was built, in what languages

  • Python 3 helpers do the work: claimocity_ingest.py parses the HL7 v2.4 DFT^P03 feed, matches charts and enters charges through the AdvancedMD XML API; claimocity_verify.py runs eligibility (AMD 271, Stedi X12 270/271); claimocity_recon.py pairs every feed message with its AdvancedMD outcome; practice_db.py turns registers and reports into documents.
  • Bash + runbooks (Markdown) tell each scheduled run what to do; the routine prompts point at the runbooks on main.
  • JSON registers on GitHub main are the record; git mirrors them to the synced branch, Postman and Drive.
  • HTML, CSS and plain JavaScript make this page; it computes every figure from the documents in the browser (no server, no library).
  • Google Cloud: a Cloud Run job copies the Claimocity SFTP files into a private bucket every 30 minutes; the routines read the bucket with a read-only key.

Capabilities the database gives the practice: a complete, searchable record of what the feed sent and what was billed; a daily health check without opening AdvancedMD; a place every routine can write to and every page can read from; raw JSON for any analysis; and the ability to add collections (credentialing, deposits, denials) without new plumbing.

The triple mirror

The record is GitHub main (dreffinger/effinger-billing-backend): code, runbooks, PHI-light registers and reports. Every change is also pushed to the synced branch the claude.ai Project reads, mirrored to the Postman workspace (API vocabulary and collections) and copied to Google Drive (runbooks, prompts, digests, the PHI state bundle). This database is the fourth copy of the structured data, and the one the pages read.
