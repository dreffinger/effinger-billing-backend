Settings

Inside claude.ai nothing needs to be set up. This page reaches Claude through your built-in Claude Code Remote connector (it starts the scheduled task and watches its run) and GitHub through your GitHub connector (it reads the reports and the packages register), both as you; claude.ai asks once whether to allow each. The token below is only for a copy of this page opened outside claude.ai, where only the GitHub reads and the engine-only button work: a fine-grained personal access token for this one repository, kept in this browser only and never sent anywhere but api.github.com.

The AdvancedMD password and the Stedi key are not entered here. The Claude run takes them from the places its prompt names (the environment credential or the saved mail threads) and never prints them; the GitHub engine reads them from the repository's locked secrets (Settings → Secrets and variables → Actions: AMD_PSW, STEDI_API_KEY). The desktop app has its own Settings with all three fields, because it runs the engine on your PC.

  1. GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.
  2. Repository access: Only select repositories → effinger-billing-backend.
  3. Permissions: Actions: Read and write, Contents: Read (Metadata is added on its own).
  4. Paste it above and press Save. Press Test; inside claude.ai it answers with the Claude task's name, outside with your GitHub login.

How it works

The button starts a Claude run. Pressing it fires the scheduled task ehpa Billing Button — full billing run (Claude) through your Claude Code Remote connector, with a one-line brief (mode, steps, packages). A fresh Claude session bootstraps the billing workspace from the repository and the Drive mirror, logs in to AdvancedMD once, and works the whole day by the standing prompts (the same rules as the 6-hourly backend run and the nightly cascade, plus the board input first): the Insurance Refresh Board rows and drops you entered, the Working Denials commands, Charge Review, Claim Inspector, Unbilled, Exclusions, ERA posting, the cascade pre-check, the ticked approval packages, the credentialing check and the Outstanding Claims refresh. Pressing the button is your order to run; if the session needs an approval for a write it asks you there and waits. It then writes reports/button/<stamp>.json + latest.json to the repository (same shape as the engine's report, with "engine":"claude"), mirrors, and posts its digest. This page follows the run on the Last run card and draws the report when it lands. The task's prompt lives in the repository as nightly/button_run_prompt_v1.txt; its model and settings are edited at claude.ai/code/routines. One run at a time: a press while another billing run is working (the 6-hourly run, the cascade or an earlier press) waits for it.

the brief
BUTTON PRESS <time> · mode: live|dry · steps: all|columns,era,… · packages: <ids> · note: ehpa Billing Button - dry reads and counts and writes nothing in AdvancedMD; a steps list limits the run; the packages are the approved cards ticked above.
engine only
The secondary button sends a workflow_dispatch to .github/workflows/billing-button.yml: GitHub lends a machine, checks out main, logs in with the password stored in the repository's secrets and runs tools/button/run_all.py - deterministic helpers in the standing order, no Claude, no judgement calls (those are listed under "waiting"). Its schedules are dry until the repository variable BUTTON_SCHEDULE_MODE is set to live; BUTTON_SCHEDULE_ENABLED=false stops them. The Working Denials and AR Aging pages' Refresh buttons still use this engine, read-only.
this PC
The desktop app (Releases → ehpa-billing-button-setup.exe) runs the same engine on your computer with the password typed into its settings (ehpa-billing://run).
privacy
The report carries chart ids, visit ids, check ids and dollars only; the privacy gate checks it before it is committed. Patient names stay in the workspace, the boards and the Drive digest.
