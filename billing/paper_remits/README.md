# billing/paper_remits — paper & virtual-card remittances into the ERA Center (9/22/2026)
Pipeline: `ocr.sh` (pdftoppm 300 dpi gray + tesseract --psm 6) -> `classify.py` (page types: check_front/back, zelis_vcard, ua_eop_cover, ua_eob_detail, wn_remit, aetna_ssi_remit, moo_remit, simply_remit, fcc_remit / fcc_zero_payment, champva_eob, bcbs_remit, medicare_remit, globe_notice, other)
-> `extract.py` (claims per payer family; `fixacct()` repairs the 8-digit+letter AMD claim number) -> `assemble.py` (one record per remittance, links Zelis stubs by payment id / mailing code and physical checks by ICN or amount)
-> `plan.py` (dedupe on (family, acct, paid) across mailings, best reference: physical check > payer check number > EOP cover > Zelis payment id; one 835 per (family, reference); holds $0/COB statements, electronic payers, unreadable accounts, no reference)
-> `build835.py` (005010X221A1; CLP01 = the EOB's Patient Acct # = AMD claim number; ONE CAS segment per reason; claim-level OA-23/253 allocated to lines by allowed) -> `post_paper.py` (upload -> checkdetails -> ERA-linked addpayments under the payer's carrier -> verify -> dismiss -> register) -> `report.py` (workbook + summary, PHI, William only).
Inputs: `SCANS_DIR` (default /home/claude/scans) with raw/<batch>.pdf; Gmail attachments > ~6 MB come through Zapier (docs/input_channels.md).
Lessons (all proven on the live tenant 9/22/2026): see docs/api_vocabulary.json 'Upload an 835' + the RECIPE entry, and practices/ehpa/rules.md.

## Re-posting held lines after the clinician's decision (`repost_held.py`, added 10/6/2026)

`post_paper.py` holds a line when applying the money needs a judgement call. Two hold shapes recur:

* **"no insurance balance and no premature write-off to void"** with a WOINS / WOMCAD / WOCAID2ND already on the line: a Medicare coinsurance or Medicaid residual was written off (with a $0 COB statement or a Medicaid $0 posting) before the paper check arrived, and the payer then paid part of it. The engine only voids a write-off that equals the payment, so a partial payment stays held.
* **"no insurance balance ... live payments [(payer, amount)]"** with the SAME payer already on the line under another check: the payer paid the service twice (one check for the original visit's claim, a later check for the re-entered visit's claim). Both checks were received.

When William says "post them", build a spec (chart ids only, see the docstring) and run `python3 repost_held.py --spec spec.json` (dry) then `--live`. For each `lines[]` entry it voids ONLY the named write-off (`void_tx.void_writeoff`), re-reads the charge (the balance must now equal the voided amount), posts the payer's money ERA-linked through `payreasons.post_line` (dismissed-check details come from the `era_details/` cache; the CO45/OA23 reasons ride along) with the leftover as the named write-off code in the same post, and verifies balance 0. Each `unapplied[]` entry posts one unapplied insurance credit on the chart (`addpayments` with `<unappliedpaymentlist><payment source="2" profile="profN" amount carrier="carN"/></unappliedpaymentlist>` and an empty `<chargelist/>`, proven 10/6/2026) — William's 9/3/2026 overpayment rule: a duplicate payment is never applied to other claims; the payer nets it or asks for a refund. The register rows then read POSTED (with the new payment id) or CREDIT; `report.py` lists CREDIT rows on the holds sheet with their note.
