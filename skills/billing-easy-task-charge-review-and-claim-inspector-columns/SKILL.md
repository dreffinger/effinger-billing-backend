## 2. CLAIM INSPECTOR
- Batches: `getclaiminspectorbatches` class=chargeentry. Claims+errors: `getclaiminspectorcharges` class=chargeentry `batchid=<ID>` → visits (claimstatus ERROR/PENDING/CLEAN), errorlist (id, number, text). Error ids change on every reinspection — always re-list first. Rebills re-run the inspector and surface new advisories — re-check after any sweep (a rebill of an old CCM visit re-raises Pattern 35790 — just bypass again).
- **Hospitalization From Date empty (117065068):** admission = MOST RECENT 99223 on/before the charge DOS (within 45 days) via `gettxhistory`; if the visit itself is the 99223, admission = its DOS. Write it with `updextrainsinfo` class=chargeentry `visitid="vst<ID>"` child `<extins txtChargeCode="<CPT>" hospitalizationfrom="MM/DD/YYYY" patsignature="1" emergency="0" epsdt="0" payprov="1" employment="0" autoaccident="0" otheraccident="0" pregnant="0" outsidelab="0"/>`. It only clears when the claim is CMS-1500 (`onhcfa=1`); if onhcfa=0, ALSO resave with onhcfa=1 (call 4). Verify: extins gets an id + the date. No 99223 anchor → HOLD and report, never guess.
- **Hospital E&M (9922x/9923x) at a non-hospital location (Pattern 4531):** hospital codes + Effinger + non-hospital location → set visit `facility="fac29"` (HCA FLORIDA CAPITAL HOSPITAL TALLAHASSEE), which auto-sets POS 21. Resave via call 4.

- **CCM duplicate/frequency advisories (Patterns 3429, 7011, 35777, 33799)** on distinct monthly CCM dates: bypass.
- **Sequela / external-cause code first (Pattern 20389):** move the S/T/V/W/X/Y code behind the condition code; Bell Jr's S81.801S-only visits get M86.9 (dcode1034545415) in front (William 9/6). **Z51.11 on a facility visit (Pattern 2776):** drop it. - **Unspecified-laterality dx (Pattern 11256):** BILLING, not documentation. Apply a known correction, else DELETE that one dcode (or bypass the advisory) so it doesn't hold billing; ALWAYS log to `/home/claude/unbilled/laterality_flag_log.md` and alert William. - 4. **Resave + reinspect + approve (= "Complete"):** `updvisitwithnewcharges` class=chargeentry, FULL charge echo (resave.CHG_FIELDS) from getchargedetaildataicd10, skip void/payment-posted, echo all visit attrs (+ onhcfa/facility/insorder/preauth as the fix needs, charge pos=21 for hospital), `approval="1" inspectorenabled="1" getfinancials="-1" customclaimfieldsavailable="1"`. ## 3. UNBILLED
- List: `getclaimunbillablecharges` class=claimsreports `lowdate="" highdate="" carrier="" provider=""` → visits + error text. **It is a cached snapshot** — fixing the data does NOT remove a row; only the release does.
- Error types: "Unresolved Claim Inspector errors" (fix/bypass in the inspector, then release); "Insurance order is missing on visit" (patient has no insplan → facesheet/Stedi → addinsurance + set visit insorder); "Patient address is incomplete" (fix with `patient_patch.family_address()` — hard-task skill); "charges have errors"; **"A payment from the prior payor is required before another claim can be submitted"** = AMD tried to bill the NEXT plan in the visit's insorder after a payment event (any posting, even a $0 denial posting or a re-posted old payment) and the first plan has no payment linked to it. Two cases: (a) primary paid long ago and the leftover is a secondary balance whose secondary window (measured from the PRIMARY'S remit — see write-off rules) has passed → write off and release; (b) primary claim recently sent and unanswered → nothing to bill yet: release (it reappears on its own if the secondary still can't bill after the primary posts). **Decide each charge off `resave.detail(cid)`: `lastbilledcarrier` (which sequence was last billed), `datebilled`, and the charge's payment list — a REAL (nonzero) payment vs only $0 postings.** Only $0 info/denial postings, or an empty `datebilled` (brand-new charge that hasn't transmitted), = case (b): release. A charge is a write-off candidate (case a) ONLY when it carries a real nonzero primary payment whose date is past the secondary window; the full CPT balance ($141/$206/$107…) still open with only $0 postings is never a write-off. Proven 9/15: 114 rows (101 new from the overnight run) → 128 charges checked, all case (b) → 103 visits released, Unbilled 114→11.
- Medicaid-only patients whose plan is an LTC carrier (FCC car42008 = custodial): physician visits go to FL Medicaid fee-for-service (car6113) when Stedi 77027 shows Full Medicaid active with no MMA plan (Tillman, Busby, Johnson, Williams, Zaykowski, Shaffer 9/7).
- Release (= the Complete button): `hideunbillablevisits` class=claimsreports `hide="-1"` child `<visitlist><visit id="<visitid>"/>...</visitlist>` (many visits per call). NEVER release a visit whose data is still broken — it just hides it. **Success reply is `<Results success="1" /><Error />` — the empty `<Error />` element is NOT a fault; detect faults on `<Fault` or `success="0"`, never on the string "error" (a substring check on "error" falsely flags every successful release).**

## Standing dx / denial / write-off rules
- I63.9 (dcode1034545006) acute stroke in POS≠21 → I69.30 (dcode1034545425), resave full echo, rebill, skip payment-posted. POS-21 KEEPS I63.9. **Never rebill UNI20 aged (pre-Aug-2026) ERA-backlog balances** — correct the dx but no rebill (they'd only deny as duplicates). FLO02 = FLORIDA MEDICARE (not Florida Blue).
- **The 12-month write-off rule is for PRIMARY claims:** over 12 months from DOS and unpaid = WOINS with a dated note (William 9/7). **A secondary / supplement balance is timely from the PRIMARY'S remit date, not the DOS** (William 9/7) — Medigap (Aetna Senior Supplemental, AARP, etc.) and Medicaid crossovers with a recent Medicare posting get REBILLED, never written off on age; Littell Ray's 9/7 write-offs were voided for this reason (`void_tx.void_writeoff`). A Medicaid crossover that paid $0 on Medicare coinsurance = contractual WOINS, never a patient balance.
