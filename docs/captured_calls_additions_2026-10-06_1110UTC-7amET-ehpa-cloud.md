- **ERA Post button + CO-45 correction, the clean way (era_co45_relink.py, new 10/6/2026).** The Post button (posterapayments) posted Medicare ACH 819919368 (ERA 1053007, 20 claims / 24 lines, $1,953.55) with the CO45 / PR2 / CO253 reasons on every payment but payreasonwoamount 0 - the 9/23 defect, now seen on Medicare too: the contractual stayed on the INSURANCE balance on 23 charges (fee - paid, e.g. 74.54 on a $160 99233) and on the PATIENT balance on the one chart with no secondary. A bare manual_post write-off would have added a $0 code-less payment per line (-> Unbilled 'Payment reason codes' rows, the 9/21 / 10/6 0510Z lesson), so the correction is VOID the Post-button payment (void class=void <payment id=.../>) and RE-POST the same remit line ERA-linked (payreasons.post_line: addpayments postingmethod="era" eraclaimid/erareportid + the remit reasonlist + WOINS = CO+PI). Result per line: payment = remit paid with its reasons, WOINS = CO45+CO253, PR2 alone left (patient side on these Medicare-only visits). 24/24 lines corrected, WOINS $1,627.77. A line whose remainder sat on the PATIENT comes back only for the paid amount after the void (insurance balance = paid, so line_amounts caps the write-off at 0) - move_to_ins.move(cid) (no seq, no rebill) before the re-post (the helper does it since this run).
